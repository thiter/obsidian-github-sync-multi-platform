## 1. 🔄 同步全部笔记 (Sync all notes)

### 1.1 功能定位
日常跨设备（Mac、Windows、iOS、Android）协作时最常用的**常规双向同步命令**。插件启动完成后也会自动在后台执行一次。

### 1.2 底层机制
- **经典 3-Way 状态比对**：
  结合本地真实文件、本地缓存元数据（`syncData.files`）与远端 GitHub Tree 进行三重比对，智能推断文件的增、删、改变动。
- **Git Tree 批量原子提交引擎**：
  在本次同步中，无论本地修改了 2 篇还是 50 篇笔记、删除了几个文件，系统会将所有变动统一打包为一个 Git Tree，**仅生成 1 个原子 Commit 提交**！
  - 彻底杜绝逐文件提交引发的 **HTTP 403 Secondary Rate Limit**（高频写入限流）与 **409 Conflict**（HEAD 指针竞争冲突）；
  - 单次同步仅消耗 2~3 次 GitHub API 请求，**节约 95% 以上的 API 免费额度**。

### 1.3 🛡️ 防灾与熔断保护 (Safety Circuit Breaker)
为杜绝“某端误操作或网络异常，引发全网多端级联删除雪崩”，该命令配备了严格的**大面积删除安全熔断门限**：
- **触发条件**：待删除文件数 $\ge 5$ 篇，或占受控笔记总数 $\ge 30\%$（且 $\ge 2$ 篇）时；
- **熔断行为**：系统立即**暂停静默删除**，弹出阻塞式告警弹窗，详细列出待删除文件数；
- **默认安全原则 (Fail-Safe)**：用户未明确确认或关闭弹窗时，**默认不删除任何本地或远端文件，事务安全回滚**。

## 2. 🛡️ 同步全部笔记(覆盖远端) (Sync all notes (overwrite remote))

### 1.1 功能定位
当本地做过大量格式整理、离线重构或冲突合并，希望**以当前本地的笔记状态为绝对基准强制更新远端**时使用。

### 1.2 核心语义：Upsert（增量覆写）而非 Mirror（抹除镜像）
许多云同步工具的“覆盖远端”容易误做成“格式化远端并用本地替代”，导致本地若误删笔记，会连带清空云端。
**本插件彻底重构了该逻辑为 Upsert 模式**：
- **本地修改的文件**：强制上传并覆盖 GitHub 远端同名文件；
- **本地新增的文件**：安全追加上传到远端；
- **本地没有但远端存在的文件**：**100% 完好保留，绝对不予删除！**

### 1.3 🛡️ 安全与防误触特性
1. **零笔记安全拦截 (Zero-Note Guard)**：
   若在新设备、空库或误删笔记目录的情况下触发该命令，插件检测到本地有效笔记为 0 时，**直接报错中止操作，绝不向远端发送任何请求**，彻底杜绝“空目录清空远端仓库”的灾难。
2. **高危二次确认弹窗**：
   在 Obsidian 命令面板中触发时，必须在弹出的红色警告对话框中点击“确认覆盖远端”，防止手滑误触。
3. **0 上传流量复用**：
   本地与远端 Git Blob SHA 一致的未变动文件，直接复用远端 SHA 引用，不耗费任何网络上传流量。

## 3. ⚡ 同步全部笔记(覆盖本地/强制初始化) (Sync all notes (overwrite local / force init))

### 1.1 功能定位
专门解决移动端（iOS / Android）初次安装冷启动、换新电脑初始化建库、或本地批量重命名混乱后希望**一键从 GitHub 远端还原完整干净副本**的需求。

### 1.2 底层机制
- **Zipball 极速解压引擎**：
  通过 GitHub Zipball API（`GET /repos/{owner}/{repo}/zipball/{branch}`），**仅用 1 次 HTTP 请求**即可把整库压缩包下载到本地，并通过轻量纯 JS 引擎（`fflate`）在内存中高速解压覆写。
- **孤儿文件清理**：
  对比本地文件列表，自动清理本地存在但远端已被删除的冗余文件，使本地与远端保持绝对一致。
- **配置隔离保护**：
  默认严格排除 `.obsidian/` 配置目录与系统隐藏文件，绝不破坏用户本地安装的插件、主题和快捷键设置。

### 1.3 🛡️ 安全与防灾保护
1. **远端异常缩水熔断**：
   解压后自动校验远端文件数。若远端有效笔记为 0，或相比本地缩水超过 70%（且本地笔记 $> 5$ 篇），**强制阻断覆盖本地**，防止因拉取被误删的远端空库而清空本地笔记。
2. **高危操作二次确认**：
   触发时强制弹出警示对话框，告知未同步的本地修改将被丢弃，用户确认后方可执行。

## 4. 实时自动化同步与系统级防线

除了手动命令，插件在日常运行中提供了坚实的底层保护：

### 4.1 单文件智能防抖与 SHA 对比
- 监听文件修改（`modify`）并设置 5 秒智能防抖；
- 每次保存前在本地预先计算 Git Blob SHA，内容无实质变动时 **0 次网络请求、0 额度消耗**。

### 4.2 文件夹删除原子化与防洪峰
- 本地删除大文件夹（包含 $\ge 5$ 篇笔记）时，触发二次确认；
- 确认后采用 Git Tree API 单次原子提交删除（1 个 Commit），杜绝循环调用单文件 DELETE 触发的 GitHub 403 API 限流。

### 4.3 全链路软删除保护 (Trash Protection)
- 任何由同步逻辑触发的本地删除操作，**全面强制升级为 `vault.trash(file, true)`**；
- 所有被删除的本地文件均完整移入操作系统的“废纸篓”或 Obsidian 的 `.trash` 隐藏文件夹，即便发生任何极端误判，用户也可以在电脑垃圾桶中一键撤销并放回！
